# 华为 CF20 手柄协议（实测确认版）

设备名 `HUAWEI CF20_902F`，实测地址 `E7:4D:4A:A7:90:2F`。以下结论全部来自
三星 SM-F731U1 上的真机抓取，不是推测。

## 连接

| 项目 | 值 |
| --- | --- |
| 广播 | 仅 BLE，公共地址，系统没有任何 profile 认领（`HID_HOST = -1`） |
| 连接方式 | 必须由 App 自己持有 GATT 客户端，`connectGatt(ctx, false, cb, TRANSPORT_LE)` |
| MTU | 默认 23 就够，不需要请求更大 MTU |
| 配对 | **不需要**，详见下一节 |

### 关于系统配对

这个手柄不能通过系统配对：每次 `createBond()` 在蓝牙栈里都以
`bt_status:auth_failure` 结束，实测连续 8 次全部失败。它的特征值也不要求加密，
所以正确做法是完全不调用 `createBond()`，直连 GATT。

华为自带的客户端里 `createBond` 出现次数为 0，与我们现在的做法一致。

## GATT 结构

Service：`622f5b2a-60da-4484-929a-69e3a9140258`

| 特征值 | 作用 | 本工程是否使用 |
| --- | --- | --- |
| `ffb4a651-c224-420b-a134-13d3aba313fb` | 输入报文通知 | 是，唯一订阅 |
| `233827e5-09cc-45a4-a59b-4d024138cbbe` | 华为客户端先订阅的通道 | 否，实测不发送任何数据 |
| `233827e4-09cc-45a4-a59b-4d024138cbbe` | 主机下发命令 | 否 |

订阅方式：`setCharacteristicNotification(ch, true)` + 向标准 CCCD
`00002902-0000-1000-8000-00805f9b34fb` 写 `01 00`，等 `onDescriptorWrite`
成功才算就绪。

注意：华为客户端会先写 `233827e5` 的 CCCD、半秒后再写 `ffb4a651` 的，容易让人
以为两个都必须写。实测只写 `ffb4a651` 就能稳定收到约 100 包/秒，另一个通道
没有任何数据。

## 报文格式

固定 20 字节，空闲时也持续发送（约 100 包/秒），不是只有操作时才发。

| 字节 | 含义 |
| --- | --- |
| 0 | 按键位，高两位固定为 `11`（标记），低 6 位是按键 |
| 1–2 | 四元数 X，大端 int16 |
| 3–4 | 四元数 Y，大端 int16 |
| 5–6 | 四元数 W，大端 int16 |
| 7–8 | 四元数 Z，大端 int16 |
| 9 | 加速度 X，有符号字节 |
| 10 | 加速度 Y，有符号字节 |
| 11 | 加速度 Z，有符号字节 |
| 12 | 陀螺仪 X，有符号字节 |
| 13 | 陀螺仪 Y，有符号字节 |
| 14 | 陀螺仪 Z，有符号字节 |
| 15 | 触控板 X（0–255） |
| 16 | 触控板 Y（0–255） |
| 17 | 电量百分比 |
| 18–19 | 未使用 |

注意四元数在报文里的顺序是 X、Y、W、Z，不是 X、Y、Z、W。

## 按键位

byte 0 的低 6 位：

| 位 | 按键 |
| --- | --- |
| `0x01` | 扳机 |
| `0x02` | 确认（触控板按下） |
| `0x04` | 音量减 |
| `0x08` | 音量加 |
| `0x10` | 主页 |
| `0x20` | 返回 |

实测原始帧 `C0 04 …` 会读到钮按 0x04（音量减）而不是 `0xC0`，说明低位的
按键位、高位的标记位互不干扰，判断按键时要先把 `0xC0` 掩掉。

## 触控板

绝对坐标，X/Y 各 0–255。`(0, 0)` 表示手指离开，其它值表示当前触点。
按下触控板会产生 `0x02`（确认）按键位，与触摸位置无关，所以「确认」要按
按键位判断，不能靠坐标。

## 体感解码

与原版 `com.huawei.vrframework.DefaultController.extractRawData` 完全一致：

```
四元数     = 大端 int16 / 32767
加速度(g)  = 有符号字节 * 16 / 127
角速度(°/s)= 有符号字节 * 2000 / 127
```

本工程把这一套写进了 `:protocol` 模块，并用真机抓到的原始帧做回归样本。

## 已验证

- 不做系统配对、只订 `ffb4a651` 时，连接后立即进入「已就绪」
- 持续 100 包/秒，电量、触控板坐标、六个按键、体感数据全部正常
- 长按不动不抖，空闲帧也不会误判成触摸
- 连续运行、反复重连没有出现「已连接但仍显示扫描中」
