# 手柄遥控

把华为 VR 手柄（HUAWEI CF20）变成任何 Android 手机都能用的遥控器和鼠标。

手柄走私有 BLE 协议，系统没有任何 profile 认领它，所以由 App 自己连 GATT、解析
报文，再把输入翻译成系统事件。翻译走 UHID：借 Shizuku 拿到 shell 身份，打开
`/dev/uhid` 建立虚拟键盘、消费者控制设备和虚拟鼠标。系统把它们当成真正的外接
键鼠，光标由系统自己绘制，不需要 root，也不需要无障碍服务。

## 功能

- 扳机键循环切换四种模式：普通模式 / 指尖鼠标 / 体感鼠标 / 跟随应用
- 普通模式把触控板当方向键，适合桌面、列表、设置这类有焦点导航的界面
- 指尖鼠标、体感鼠标分别用触控板和手柄姿态驱动系统光标，支持点击与拖动
- 跟随应用可以给单个 App 配置 7 个触发、15 种动作，内置小说、短视频、相机模板
- 手柄测试页实时显示按键、触控板轨迹、体感数据和原始 20 字节报文
- 前台服务保持连接；主页「完全退出」会停止服务并结束进程，不会被系统重新拉起

## 安装

要求 Android 8.0 及以上，并已安装、启动 [Shizuku](https://shizuku.rikka.app/)。
APK 从本仓库的 Releases 页面下载，安装后按下面的步骤授权即可。

## 使用

1. 启动 Shizuku（无线调试或 root 均可），在 App 里授权；
2. 打开 App，点「开始扫描」，发现手柄后自动连接；
3. 按手柄扳机键切换模式，屏幕底部会出现当前模式提示；
4. 需要给某个 App 单独配置时，打开「设置 → 应用名单」；
5. 不用时点主页最下方「完全退出」。

没有 Shizuku 时手柄测试页仍然可用（连接、按键、触控板、体感都能看），但遥控和
光标不会生效。

## 四种模式

| 模式 | 触控板 | 体感 | 触控板按下 |
| --- | --- | --- | --- |
| 普通模式 | 上/下/左/右滑动 → 方向键 19/20/21/22 | 不处理 | 回车 66 |
| 指尖鼠标 | 相对位移驱动光标 | 不处理 | 鼠标左键 |
| 体感鼠标 | 不驱动光标 | 四元数增量驱动光标 | 鼠标左键 |
| 跟随应用 | 按当前 App 的配置 | 不处理 | 按当前 App 的配置 |

返回 4、主页 3 在所有模式下都可用。音量键在跟随应用模式下按配置执行，没有配置时
保持系统音量，不会被吞掉。

## 跟随应用

切到「跟随应用」后，手柄按当前前台 App 自己的配置工作；名单外的 App 不做任何响应，
扳机键仍然可以切走。可配置的触发是：触控板上/下/左/右滑、触控板按下、音量加、
音量减。

可绑定的动作分两类：

- **安卓按键**（推荐）：音量、静音、播放/暂停、上一个/下一个、快进/快退、上一页/
  下一页、方向键、返回/主页/确定/菜单/最近任务。这些在任何手机上行为一致。
- **屏幕手势**：上/下/左/右滑动，点击屏幕左/中/右/下，双击，长按。它们按屏幕坐标
  执行，只对特定 App 有意义（比如短视频点赞），所以名字里都标了「屏幕手势」。

按键全部走虚拟 HID 设备（键盘页 + 消费者页用法），由系统自带的按键布局翻译成安卓
键值。实测 `dumpsys input` 的 KeyBitmask 已包含菜单 139、静音 113、播放/暂停 164、
下一个 163、上一个 165、快进 208、快退 168、上一页 104、下一页 109、最近任务 580。

关于拍照：所有厂商的相机都把音量键当快门，市面上的蓝牙自拍器也是发音量键，所以
相机模板用音量键当快门。老式实体相机键（`KEYCODE_CAMERA = 27`）和对焦键
（`KEYCODE_FOCUS = 80`）现代相机基本不认，已经从动作表里移除。

## 关于系统配对

这个手柄不支持系统配对：`createBond()` 在蓝牙栈里一律以 `auth_failure` 结束（实测
连续 8 次全部失败），它也不会出现在系统蓝牙的「已配对设备」里。华为官方客户端的
代码里同样没有调用过配对，它也是自己持有 GATT 连接。所以连接、保活、重连都由 App
负责，这是这个设备的固有形态，不是本项目的实现缺陷。

## 关于模式提示

提示条是 App 自己画的悬浮窗，需要的 `SYSTEM_ALERT_WINDOW` 权限由 Shizuku 自动授予
（`appops set … allow`），不需要手动去系统设置里点。

### 为什么不用系统 Toast

Android 12 之后 Toast 由 SystemUI 渲染。测试机上装的 DeX 模块
（`com.flexunlock.dexlsp`）hook 了 `NotificationManagerService.enqueueToastForDex`，
经它转发的 Toast 文本第一个字会被改掉一个字节（「指尖鼠标」变成「挈尖鼠标」）。
App 里的字符串本身是好的，所以提示全部改成自绘，绕开这条通道。

## 已知问题

- 体感鼠标的方向在部分非三星机型上是反的（三星折叠屏实测正常）。目前没有按机型
  自动判断正负号，遇到时可以先改用指尖鼠标。

## 项目结构

| 模块 | 作用 |
| --- | --- |
| `:protocol` | 20 字节报文解析，纯 Kotlin，带真机样本回归测试 |
| `:remote` | 四种模式的映射引擎、每 App 配置与编解码，纯 Kotlin，可单测 |
| `:app` | 蓝牙连接、Shizuku + UHID 注入、前台服务、界面 |

数据流和线程模型见 [docs/architecture.md](docs/architecture.md)。

## 构建

```powershell
$env:JAVA_HOME='D:\Code\华为VR\华为VR_兼容版本\工具链\android-sdk\jdk17tmp\jdk-17.0.20.1+1'
$env:ANDROID_HOME='D:\Code\华为VR\华为VR_兼容版本\工具链\android-sdk'
gradle -p D:\Code\vrremote-kotlin :app:assembleDebug
gradle -p D:\Code\vrremote-kotlin :protocol:test :remote:test
```

工程真实位置是 `D:\Code\华为VR\vrremote-kotlin`；AGP 处理不了中文路径，所以构建
统一走 junction `D:\Code\vrremote-kotlin`。
